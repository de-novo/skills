## 실행한 것

기존 소비 프로젝트와 공유 엔진은 사용하지 않았다. 임시 Git 저장소를 baseline으로,
실제 `git worktree`를 자리로, Grove의 격리 process 백엔드(`infra/bin/fixtures/process-overlay.mjs`)를
overlay 명령으로 썼다. 레지스트리는 `GROVE_STATE_DIR` 아래 임시 디렉터리다.

```bash
npm test
node --test infra/bin/dryad.test.mjs
node --test infra/bin/overlay.test.mjs
node --test infra/bin/overlay-parallel.test.mjs
```

## 실제 에이전트를 자리에 앉힌 수동 실행

같은 날 사람이 한 번 실행했다. 자동 검사가 아니며, 런처는 설계상 Dryad 밖이므로
Dryad의 회귀 검사에는 들어가지 않는다. 이 기록은 "자리 계약이 실제 도구에
그대로 먹히는가"에 대한 한 번의 관측이다.

준비: 임시 저장소 하나에 `runtime-profile.yml`(`overlay: none`)과
`dryad-profile.yml`(`worktrees` 절 없음, 전부 입양), `.agents/skills/dryad` 심링크,
짧은 `AGENTS.md`. 데스크톱 워크트리 관리 앱에 이 저장소를 등록하고, 앱이
워크트리를 만들게 한 뒤 Dryad가 입양했다. 자리는 앱이 연 셸에 `seat --shell`
한 줄을 보내고 그 뒤에 도구를 붙이는 방식으로 넘겼다.

```bash
de-novo skills dryad plan w1 --task-file ../w1-task.md --worktree <app-made-path> --by claude --apply
# app shell:  eval "$(de-novo skills dryad seat w1 --shell --project <baseline>)" && claude --dangerously-skip-permissions "$(cat ../w1-task.md)"
de-novo skills dryad plan w2 --task-file ../w2-task.md --worktree <app-made-path> --by codex --apply
# app shell:  eval "$(de-novo skills dryad seat w2 --shell --project <baseline>)" && codex --dangerously-bypass-approvals-and-sandbox "$(cat ../w2-task.md)"
de-novo skills dryad status
de-novo skills dryad finish w1 --apply && de-novo skills dryad finish w2 --apply
```

작업 본문은 여섯 줄이다. 환경변수를 echo하고 스킬을 읽고, `seat --json`으로 자기
브랜치를 확인하고, NOTES.md에 한 줄을 붙여 그 파일만 커밋하고, `report done`을
치고, 커밋 해시를 답한 뒤 멈춘다. 푸시와 finish는 금지했다.

| 관측 | w1 (Claude Code) | w2 (Codex) |
| --- | --- | --- |
| `DRYAD_ID` `DRYAD_PROJECT` 도달 | 도구가 echo로 출력 | 도구가 echo로 출력 |
| 스킬 읽음 | 읽음 | 읽음(+79줄 출력) |
| `seat --json`으로 브랜치 확인 | w1 | w2 |
| 커밋 | `d26d654 w1: note`, NOTES.md만 | `4623dfe w2: note`, NOTES.md만 |
| `report done` 자기 보고 | 저널에 `seat report done: NOTES.md updated` | 같음 |
| 푸시·finish 안 함 | 지킴 | 지킴 |
| `dryad status` | `reported done 2`, `+1` 둘, exit 0 | |
| `finish --apply` | 입양 워크트리 유지, 브랜치 유지, 자리 제거 2/2 | |

사람이 개입한 곳 둘. 두 도구 모두 처음 여는 디렉터리에 신뢰 확인을 띄웠고,
사람이 앱 터미널에 키를 보내 답했다. 이건 런처의 일이고 Dryad는 모른다. 앱의
`tui-idle` 대기는 Codex가 아직 작업 중일 때 한 번 조용한 구간을 유휴로 판정했다.
완료 판정을 프로세스나 화면이 아니라 작업자의 `report done`으로 두기로 한 결정이
여기서 실제로 값을 했다. Dryad `status`를 폴링해 `done`을 기다리는 것으로 충분했다.

두 도구는 자리에서 전권 플래그로 실행했다. 임시 저장소였기 때문이며, 어떤
권한 정책으로 앉힐지는 런처와 사람의 값이다.

## 재지 않은 것

- 실제 에이전트 도구를 자리에 앉히는 것은 위 수동 실행 한 번뿐이다. 회귀 검사에는
  없고 앞으로도 Dryad 검사에 넣지 않는다. 런처는 설계상 밖이다.
  이유는 [설계 기록](../dryad-design.md)에 있다.
- overlay가 켜진 프로젝트에서 실제 도구가 `overlay attach`까지 하는 경우. 위 실행은
  `overlay: none`이었다.
- 공유 백엔드(k3d, compose)의 adapter 동시 실행. 이전과 같은 경계.
- 다른 호스트가 잡은 락의 liveness. 레지스트리가 머신 로컬이라 `unknown`으로만
  표시한다.
